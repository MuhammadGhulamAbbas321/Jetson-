# Speed test for the Jetson Nano (`speedtest.py`)

Measures latency, download and upload speed with standard-library Python only.
Nothing to install. Run it on the Nano once the internet works through the ESP32.

> Status: not yet run on real hardware. It needs to reach Cloudflare (download and upload)
> or Tele2 (download fallback) from your network.

---

## Run

```bash
python3 speedtest.py
```

## Options

| Command | What it does |
|---|---|
| `python3 speedtest.py` | 2 MB download, 0.5 MB upload |
| `python3 speedtest.py --down-mb 5` | Larger download: more accurate, slower |
| `python3 speedtest.py --up-mb 1` | Larger upload |
| `python3 speedtest.py --skip-upload` | Latency and download only |

## What it prints

| Line | Meaning |
|---|---|
| `Route to the internet` | Which interface traffic uses. If it is not `ppp0`, the test is **not** measuring the ESP32 link |
| `Latency` | Time to open a connection to 1.1.1.1, five tries (min and average, in ms) |
| `Download` | Speed in Mbit/s, with the size, time and server used |
| `Upload` | Speed in Mbit/s, with the size and time |

## What to expect

- At 921600 baud the serial link is the limit. Expect **well under 1 Mbit/s**.
- At that speed 2 MB takes about 30 seconds or more. This is normal.
- Numbers are rough. They include PPP and TLS overhead and the connection setup of each request.
- Latency over a serial PPP link is usually higher than on Ethernet.

## Compare with your normal connection

1. Start `pppd` **without** `defaultroute replacedefaultroute`, so your normal internet stays the default. Run `python3 speedtest.py`.
2. Restart `pppd` **with** `defaultroute replacedefaultroute`. Run it again.
3. Compare the two. The second run is the ESP32 link.

## Troubleshooting

| Problem | Fix |
|---|---|
| `No internet connection` | Run `python3 espwifi.py status` (want `connected=1`) and `ip route` (want `ppp0` as default) |
| Route is not `ppp0` | Restart `pppd` with `defaultroute replacedefaultroute` |
| Download fails on both servers | Check DNS: `ping google.com`. If only the name fails, set `nameserver 8.8.8.8` in `/etc/resolv.conf` |
| Upload fails but download works | The upload server may be blocked on your network. Use `--skip-upload` |
| Very slow or timeouts | Try a smaller size with `--down-mb 1`. Weak WiFi signal at the ESP32 also lowers speed |
| Speed far below 0.5 Mbit/s | Check the WiFi signal with `python3 espwifi.py scan` and keep the ESP32 close to the router |

## Notes

- The test sends only generated bytes (zeros) for upload and downloads test files. It does not use your personal data.
- Do not run it repeatedly with large sizes on a metered connection such as a phone hotspot.
